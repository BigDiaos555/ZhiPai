# 架构说明

写给要改这个项目的人。产品逻辑几乎全在 `web/app.html`，原生外壳不承载业务规则。

## 1. 状态模型

单一全局状态挂在 `DB.S` 上，落盘键：

| 键 | 内容 |
| --- | --- |
| `zhipai.state.v3` | 当前学期的完整状态（`DB.S`） |
| `zhipai.semesters.v1` | 多学期索引，切换 / 新建学期走 `Semesters` |
| `zhipai.demo.*` | 演示版使用同名键加 `demo` 前缀，与正式版数据隔离 |

主要字段：

```
meta          校名、学期名、开学日期、周数、每周天数、每天节数、节次时段
grades/classes/teachers/subjects/rooms   基础数据（班级含正副班主任 head/vice）
tasks         排课任务：班级 × 学科 × 教师 × 周课时
lessons       已排课程：{ classId, teacherId, subjectId, day, slot, week? }
adjustments   临时调课
groupLeaders  备课组长({ '年级|学科': 教师 })、学科组长
exam          监考安排：科目 + 附加信息(subjectMeta) + 场次(sessions) + 考场 + 结果(result)
seating       考场编排：花名册、分层参数、考试名、编排结果(plan)
```

**新增字段一律走 `normalizeState()` / `normXxx()` 自愈**：老数据缺字段时补默认值，旧格式顺手迁移（例如监考科目早年是 `subject: string`，现在是 `subjects: string[]`）。这样多学期快照和老用户 localStorage 都不会被打爆。

## 2. 排课

- 输入是 `tasks`（每条 = 某班某学科每周 N 节，指定教师）。
- 算法：贪心放置 + 多轮随机重启，评分项包含教师 / 班级 / 场地冲突、连堂、单双周、教研活动禁排、语数英偏上午、技能课偏下午、同科不扎堆。
- 结果是 `lessons` 数组，冲突检查 `detectAllConflicts()` 独立于排课逻辑，随时可复算。

## 3. 监考安排

规则集中在 `examGenerate(seed)`：

1. 巡考是**硬约束**：必须是本场「本年级 + 本学科」的备课组长或学科组长（`examPatrolCandidates`），没有普通教师兜底，缺人直接报错。
2. 监考排除外教（`examIsForeignTeacher`），排序依次为工作量 → 同学科（`canonSubject`）→ 随机种子。
3. 本场需要的监考人数按「本场参考年级对应的考场」重算；科目没勾年级时才覆盖全部考场。
4. 生成结果可拖动换人（`examSwapTeachers`），只允许同角色且时段不冲突，换过会打 `touched` 标记。

考试时长支持「学科 × 年级」独立设置（`subjectMeta[name].minutesByGrade`），未设置的年级沿用该科目的默认时长。

## 4. 考场编排

- 纯 JS 读 xlsx：内置 ZIP 解析 + DEFLATE（`seatUnzip` / `seatReadXlsx`），不依赖任何库。
- 编排：按年级分层、随机分配考场与座位，考号 = `K + 年级代码 + 考场(2 位) + 座位(2 位)`；同 seed 可复现，换一批 = seed+1。
- 产出：
  - 考号对照表 → XLSX（带样式、冻结窗格）；
  - 名单页 / 分布页 / 桌贴 → **一份** A4 黑白 PDF（网页侧拼好独立 HTML，原生逐页转 PDF）。

## 5. 导出管线

### 课表

`sheetSVG` 是唯一渲染器：PNG、打印、XLSX 都从同一份 spec 出发，所以三者版式一致。`xlSpecToSheet` 把同一份 spec 转成 22×8 的工作表；字号由 `ttsFontSizes` 全表统一自适应。

### XLSX

零依赖手写 OOXML（`Export.buildWorkbook`）。有几处顺序 / 语义是 Excel 的硬要求，改的时候留意：

- `<pane xSplit>` 是**冻结列数**，不是列号：`freeze: 'B3'` → `xSplit="1" ySplit="2" topLeftCell="B3"`，为 0 时整个属性省略，否则 Excel 会提示「内容有问题」并把文件标成 `[已修复]`。
- `autoFilter` 必须排在 `mergeCells` 之前。
- `<rPr>` 子元素顺序是 `rFont → b → color → sz`（CT_RPrElt 是有序序列）。

### PDF

网页给原生一份**独立 HTML**，里面自带纸面规则：

```
@page { size: A4 portrait; margin: 0 }
.er-page { width: 210mm; height: 297mm; page-break-after: always }
html { zoom: 0.75 }
```

`zoom: .75` 是关键：WebKit 里 1 CSS px 对应 1 个逻辑单位，而 1pt = 4/3 px。把整页缩到 0.75，210mm × 297mm 正好落成 595.28 × 841.89 个逻辑像素，与 A4 的点数一一对应。于是原生只要把离屏 WebView 撑到整份文档高度，按 `.er-page` 的位置切 595.28 × 841.89 的矩形，一次 `createPDF` 就是一张标准 A4，用 PDFKit 合并即可。

`mac/main.swift` 的 `DocPrinter` 把这个过程做成通用的：

- `selector` 指定「页块」元素（导出 PDF 用 `.er-page`，打印用 `.print-page, .tts-page`）；
- 量出每个页块的位置和内部 `<tr>` 的位置；
- 长表格按行换页，切口落在下一行的顶边，**不劈行**；
- 抓下来的页面（高度可能略小于 A4）依次贴到 A4 画布顶部，底部留白，避免把半行裁掉。

## 6. 原生外壳的注意点

- **必须**用 `WKWebsiteDataStore.default()` 且 bundle id 稳定：它是旧版本数据的来源（首次启动时由垫片搬进包内仓库），也是运行期缓存。换成 `nonPersistent` 会断掉升级路径。
- 数据仓库（`Vault`）：权威副本在 `Contents/Resources/userdata/store.json`，网页的 `localStorage` 由 document start 注入的垫片接管。读完 `docs/数据与迁移.md` 再改这块。
- 注入脚本每次 `reload()` 前都要重建（`installUserScripts`），否则重载会拿旧快照覆盖新数据。
- 往 `Contents/Resources` 写数据必然让代码签名封条失效 → 外壳自动 `codesign --force --sign -` 重签（写后 20s 空闲 / 退出 / 启动自检）。不重签的话，拷到别的 Mac 上会被判「已损坏」而不是「未验证开发者」。
- `<input type=file>` 在 WKWebView 下：不能 `display:none`，要插进 DOM、`position:fixed; opacity:0`，并保留强引用。网页侧统一走 `pickLocalFile()`。
- `<a download>` 无效，下载统一走 `Export.download`：Blob → base64 → 原生保存面板。
- `window.print()` 无效，打印统一走原生桥（见 README 里「为什么打印要绕一圈」）。

## 7. 回归方式

改完代码至少跑一遍：

```bash
cd mac && ./build.sh
BIN="../dist/智能教务.app/Contents/MacOS/zhipai"
"$BIN" --selftest && cat /tmp/zhipai-selftest.log
"$BIN" --pdftest  && cat /tmp/zhipai-pdf.log
"$BIN" --printtest && cat /tmp/zhipai-printcheck.log
"$BIN" --vaulttest && cat /tmp/zhipai-vaulttest-1.log /tmp/zhipai-vaulttest-2.log
```

`--selftest` 会额外验证保存桥（写 `/tmp/zhipai-save-test.bin`）；`--vaulttest` 会往仓库里写一个 `__vaulttest_marker__` 再重载页面，确认垫片与种子脚本都对（测完可以把这个键从 `store.json` 里删掉）；`--pdftest` 会真的排 1800 个座位并生成 186 页 PDF，页数或首张纸尺寸变了就说明分页几何被动过。
